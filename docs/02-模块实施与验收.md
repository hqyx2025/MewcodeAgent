# MewCode Agent：模块实施与验收计划

状态：M01–M07已完成本地验收；M07远端CI核对中；M08–M17待实现。主技术栈：TypeScript + Node.js。

本计划根据[公开网页及目录图片](00-网页内容提取.md)独立补充具体步骤。M01–M17 对应公开的 17 章主题；细节、验收和调优指标是本仓库方案，不是课程内部施工步骤。

## 1. 实施规则

每次推进一个模块，保持能运行、能演示、能回退。涉及后续模块的接口先保持最小，不提前实现复杂框架。

模块开始时建立三份文档：

- `docs/modules/Mxx/spec.md`：目标、非目标、输入输出、错误行为、权限、依赖、演示。
- `docs/modules/Mxx/tasks.md`：按可验收的小步骤列任务，标注当前状态与阻塞点。
- `docs/modules/Mxx/checklist.md`：功能、边界、跨平台、调优、文档和演示验收记录。

每个模块执行：核对规格 → 最小实现 → 跑必要检查 → 固定场景验收 → 记录基准 → 按测量结果调优 → 更新文档和状态 → 查看差异。

代码阶段的常规检查计划为：类型检查、lint、相关单元/集成测试、构建，以及本模块演示。纯文档变更只检查链接、结构和事实来源。真实模型测试必须使用独立配置，日志中不保留密钥。

## 2. 总体路线与完成门槛

| 阶段 | 模块 | 可见成果 | 进入下一阶段的门槛 |
| --- | --- | --- | --- |
| A：核心闭环 | M01–M06 | 流式对话，查找并修改代码，执行校验，权限审批与Plan模式 | 模拟任务完整闭环；所有执行路径走权限入口；核心错误能恢复 |
| B：长任务与扩展 | M07–M12 | MCP、长会话、记忆、命令、技能、钩子 | 压缩不破坏调用链；恢复不重复执行；扩展不能绕过权限 |
| C：协作 | M13–M15 | 子任务并发、Worktree隔离、多Agent任务协作 | 有界并发与预算；分支和任务归属明确；无静默覆盖或丢失 |
| D：收敛与讲解 | M16–M17 | 可安装版本、评估结果、设计复盘与项目展示 | 固定任务回归通过；安装可复现；设计亮点有代码和数据支撑 |

依赖主线：M01 → M02 → M03 → M04 → M05 → M06；之后完成 M07–M12，再进入 M13 → M14 → M15 → M16 → M17。

为避免在 M06 前出现无保护的写入，M03 就建立最小授权入口，默认写入和命令执行需要确认；M06 再完善分层权限。M08 前至少具备消息/工具输出上限和轮数预算，不能等完整压缩系统才控制资源。

MVP 定义：终端接收任务 → 查找和读取项目文件 → 展示并授权修改 → 运行明确授权的命令 → 依据工具结果继续 → 输出完成说明或失败原因。第一版无需 MCP、长期记忆或多 Agent 才能验收核心闭环。

## 3. 各模块施工图

### M01：初识 Coding Agent / 基础工程

**网页主题**：第 1 章“初识 Coding Agent”。

**交付**：Node.js/TS 单包工程、CLI 入口、配置校验、错误与事件基础类型、开发检查命令、环境说明。

**步骤**：

1. 核对 Node.js 24、Ink/React、SDK、构建与测试依赖的兼容性，锁定版本。
2. 建立 ESM、严格 TS、tsx、tsup、Vitest、lint和格式化配置。
3. 增加 npm bin 与 help/version，形成编译产物和开发启动方式。
4. 配置分为内置默认、用户文件、项目文件、环境变量、CLI覆盖；字段校验失败明确报错。
5. 定义工作目录、存储目录、日志路径和 provider配置；配置只引用API密钥环境变量名称。
6. 定义模块导入边界，增加最小模拟 provider，为后续离线开发提供入口。

**验收**：无密钥可运行帮助、版本与离线演示；缺少配置、错误类型、中文/空格路径可得到明确结果；安装后 CLI 找到正确资源目录。

**调优**：记录构建时长、CLI启动时间、产物大小；优先移除重复打包和非必需启动初始化。

### M02：让 AI 开口说话

状态：已完成；支持Chat Completions/Responses，用户的gpt-5.5 Responses端点已试连。见[规格](modules/M02/spec.md)、[任务](modules/M02/tasks.md)和[验收记录](modules/M02/checklist.md)。

**交付**：Ink流式对话界面、多轮会话、首个模型适配器、取消/错误/重试行为。

**步骤**：

1. 确认用户首个模型、base URL、工具调用能力和窗口配置；创建本地模拟流。
2. 定义统一消息格式与 LLMEvent，适配文本分片、usage和结束原因。
3. Ink组件消费事件，支持输入、历史、状态和退出；输入与输出状态分开。
4. 实现多轮上下文、AbortSignal、网络超时与分类错误。
5. 限定可重试时机；输出已经开始后，不悄悄重试拼接重复答案。
6. 检测非TTY场景并降级为纯文本，保证输出可管道使用。

**验收**：流式中文、空文本、多轮追问、401、429、超时、半途断流和 Ctrl+C；错误不损坏现有会话，取消不误写成成功结束。

**调优**：测量模拟流到首个输出的本地延迟、渲染次数和输入响应；合并高频分片，保留最终完整文本。

### M03：工具系统

状态：已完成；六工具、基础权限、明确调用CLI与万文件搜索调优见[规格](modules/M03/spec.md)、[任务](modules/M03/tasks.md)和[验收记录](modules/M03/checklist.md)。模型自主调用在M04接入。

**交付**：工具Schema与注册表、统一执行器、六个核心工具、基础权限入口。

**步骤**：

1. 定义工具输入、输出、错误码、callId与执行上下文。
2. 先实现 ReadFile、Glob、Grep，限制输出大小并保留检索路径/行号。
3. 实现 WriteFile、EditFile：原子写入、覆盖确认、唯一匹配、读取版本检查。
4. 实现 Bash的ShellAdapter：Windows PowerShell / 明确配置的Bash，cwd、编码、退出码、超时和进程取消。
5. 添加基础allow/ask/deny入口，所有写入和命令执行由此进入。
6. 把工具输入转换成模型工具定义；此阶段用明确调用演示，不提前实现完整自主循环。

**验收**：六工具逐一覆盖；无匹配/重复匹配、文件并发变化、二进制与大文件、非法正则、路径越界、符号链接、中文路径、命令失败和超时。Windows环境中取消后确认子进程树被清理。

**调优**：使用固定夹具生成万文件仓库，记录Glob/Grep的耗时和输出；优先限制范围、忽略依赖目录和控制结果大小。

### M04：让 AI Agent 自己干活

状态：已完成；协议、预算和权限见[规格](modules/M04/spec.md)、[任务](modules/M04/tasks.md)与[验收记录](modules/M04/checklist.md)。

**交付**：ReAct式Agent Loop、工具调用流式组装、状态机、预算、Plan模式和完整事件流。

**步骤**：

1. 将文本、工具调用与工具结果接入统一消息序列，保留callId。
2. 完整组装并校验工具参数后才执行；识别多个调用及相关依赖。
3. 回填结果并进入下一轮，允许模型根据失败信息修正。
4. 实现正常结束、截断、错误、重复失败、轮数/时间/token预算和取消。
5. Plan模式只暴露只读能力，并由执行器再次阻止写入。
6. 添加Anthropic适配器验证内部协议转换；不要求两家密钥才能运行离线回归。

**验收**：固定模拟任务“搜索 → 读取 → 修改 → 测试 → 汇报”完整闭环；错误callId、参数分片损坏、工具失败、纯文本结束、token截断、取消和轮数耗尽有确定结果。

**调优**：分析无效调用、重复工具结果、事件队列增长；只并发明确独立的只读调用。

### M05：System Prompt 设计

状态：已实现分段提示、项目指令发现、来源元数据与固定回归；见[规格](modules/M05/spec.md)、[任务](modules/M05/tasks.md)和[验收记录](modules/M05/checklist.md)。

**交付**：可组合的系统提示词、环境与项目指令注入、提示词回归任务集。

**步骤**：

1. 拆分身份/能力、任务执行、工具规范、权限/模式、环境五类提示段。
2. 注入OS、shell、cwd、工具能力和预算，避免模型假定Linux环境。
3. 定义项目AGENTS.md与兼容CLAUDE.md的发现及优先级；指令来源清楚可追踪。
4. 明确文件内容和外部服务返回不能改变执行权限；不要求输出隐藏思维链。
5. 建立固定任务：小型修复、探索项目、错误纠正、Plan模式与恶意文件指令。

**验收**：能解释注入来源；超长指令截断有提示；项目指令冲突处理一致；恶意文本不能在执行器处提升权限。

**调优**：对比提示长度、任务成功率、工具调用数和费用；仅保留有证据提升行为的提示段。

### M06：权限系统

状态：已实现累积规则、精确会话审批、继承限制与审计；见[规格](modules/M06/spec.md)、[任务](modules/M06/tasks.md)和[验收记录](modules/M06/checklist.md)。

**交付**：五层策略、审批界面、规则持久化、审计、模式切换。

**步骤**：

1. 完善模式/能力、路径、参数风险、审批、执行限制五层补充方案。
2. 明确deny优先、项目规则不能覆盖更严格的用户限制、子Agent不能扩权。
3. 处理真实路径、symlink/junction、大小写、盘符、UNC与非存在目标的父目录。
4. 审批展示最终cwd、命令、路径、编辑diff和授权范围；参数变化时重新授权。
5. shell复合语法、重定向和未知命令走审批；不把简单命令黑名单当成完整防御。
6. 记录allow/ask/deny结果；为MCP、Hook、Worktree预留同一入口。

**验收**：Plan模式禁止写入；deny规则不可覆盖；路径别名、Hook改参、拒绝、超时和取消不能绕过审批；非TTY遇到ask可明确停止并说明原因。

**调优**：记录审批次数、重复询问和策略耗时；只缓存范围清楚的授权。通过本阶段后验收核心MVP。

### M07：MCP 协议

**交付**：MCP客户端、工具发现与注册、调用映射、连接生命周期。

**步骤**：

1. 配置stdio服务的可执行路径、参数、cwd和最小环境变量；启动动作本身需授权。
2. 使用官方SDK完成initialize、tools/list、tools/call；统一命名空间和Schema。
3. 所有调用进入统一权限入口，未知外部工具标记为需要确认。
4. 实现超时、取消、关闭、连接失败隔离及重新发现。
5. stdio稳定后增加Streamable HTTP，明确鉴权配置和响应限制。

**验收**：用本地模拟服务测试发现、成功、isError、畸形结果、重名、断连和重连；CLI退出后不遗留服务进程；单服务失败不阻断其他工具。

**调优**：测量服务启动与发现耗时，控制连接数和结果体积；按需连接可选服务。

### M08：上下文管理

**交付**：token预算、完整调用链保留、自动/手动压缩、结果溢写、会话存储与恢复。

**步骤**：

1. 配置模型窗口和输出预留，区分真实usage和本地估算。
2. 定义系统指令、目标、摘要、近期消息、工具结果的预算和优先级。
3. 长结果写入会话文件并保留摘要和索引；禁止无限注入文件全文。
4. 压缩采用生成候选 → 校验 → 原子落盘 → 切换的流程，失败保留旧上下文。
5. JSONL存储schemaVersion、事件与检查点；恢复时不再次执行已完成的动作。
6. 会话清理同步清理溢写引用；处理磁盘满、尾行损坏和崩溃中断。

**验收**：长对话触发压缩后仍保留目标、权限和未完成任务；完整tool call/result对不丢；摘要失败可回退；恢复不重复写文件、命令或MCP调用。

**调优**：用固定100轮模拟会话与大工具输出对比压缩前后大小、摘要耗时和信息保留；记录压缩调用成本。

### M09：记忆系统

**交付**：项目/用户记忆、候选提取、按需注入、查看与删除。

**步骤**：

1. 定义用户偏好、项目约定、经验证事实与临时任务的区别。
2. 分开用户与项目Markdown文件，限制大小和注入优先级。
3. 从会话生成候选，去重并记录来源，经允许后更新。
4. 提供查看、编辑、删除方式；过滤密钥、敏感数据和未经验证推断。
5. 将记忆放在独立区域，压缩后仍按预算重新注入。

**验收**：跨会话保留已确认偏好；项目A信息不泄漏到项目B；删除后不再注入；压缩不丢失刚加载的有效记忆。

**调优**：记录注入token数和相关命中；先优化筛选与去重，不提前引入向量数据库。

### M10：Slash Command

**交付**：内置命令、自定义模板、参数解析、帮助与补全。

**步骤**：

1. 实现/help、/clear、/model、/permissions、/compact、/resume、/plan。
2. 注册命令名、说明、参数和执行器；区分本地状态命令与模型任务。
3. 加载项目/用户自定义Markdown命令，明确同名优先级。
4. 参数替换只用于文本模板；后续工具动作仍经过权限策略。
5. 测试工具执行中、审批中和压缩时的命令行为，避免状态竞争。

**验收**：未知命令、缺少参数、中文参数、清空和恢复、模式切换正确；自定义命令不会直接获得shell权限。

**调优**：按需读取模板，减少每次输入的重复扫描；记录解析延迟。

### M11：Skill 系统

**交付**：SKILL.md发现、元数据索引、匹配/显式选择、按需读取资源。

**步骤**：

1. 定义项目/用户Skill目录及同名规则，校验frontmatter和描述。
2. 启动仅索引name/description；触发时再加载正文。
3. 支持明确指定技能和基于描述选择；记录本轮使用的来源。
4. 限制资源路径在技能目录内；缺失或过大资源明确报错。
5. 技能附带脚本通过现有工具执行，不能绕过权限；实现索引刷新。

**验收**：显式加载、未匹配不注入、坏元数据、同名、缺失资源、目录穿越和指令冲突；文档能说明SKILL.md与MCP的区别。

**调优**：记录索引时长、内存与按需加载的token节省，验证不全量读取资源。

### M12：Hook 系统

**交付**：生命周期事件、Hook配置、执行器、结构化决策和审计。

**步骤**：

1. 明确SessionStart、PreToolUse、PostToolUse、Stop、SessionEnd的触发时机。
2. 定义输入输出Schema、阻止/改参规则、超时与失败策略。
3. 脚本执行使用授权入口；只传必要字段及显式环境变量。
4. 改参后重新校验和授权；只读模式中的写入Hook禁止执行。
5. 防止递归触发；并行/取消时保持事件归属和顺序。

**验收**：阻止工具、合法改参、改参越界、无效JSON、超时、脚本失败、取消和正常结束；安全相关Hook失败默认阻止对应动作。

**调优**：记录Hook延迟与调用次数，减少重复启动；不能以性能优化跳过必要检查。

### M13：SubAgent

**交付**：独立子会话、任务委派、只读有界并发、结果汇总和预算继承。

**步骤**：

1. 定义子任务目标、工具白名单、输入上下文和结果Schema。
2. 独立上下文与状态，继承父权限，限制深度、数量、时间和总费用。
3. 增加队列、并发上限、进度与取消传播；本阶段只允许只读任务。
4. 汇总结果及证据引用；单任务失败可恢复，避免一处错误静默丢弃其他结果。
5. 对工具和事件加入agentId，隔离状态与输出。

**验收**：并行探索多个目录、一个子任务失败、父任务取消、预算耗尽、权限收紧和重复提交；父上下文只注入必要摘要。

**调优**：比较同任务串行/并发耗时、总token、队列长度和内存；并行收益需扣除额外模型与汇总成本。

### M14：Git Worktree

**交付**：Worktree创建/复用/回收、归属记录、写入子任务、diff与冲突展示。

**步骤**：

1. 检测Git版本与仓库，校验基准ref；定义分支名和工作树根路径。
2. 创建隔离分支和worktree，记录agentId、任务、基准、路径与状态。
3. 启用写入子任务；文件和进程工作目录都绑定相应工作树。
4. 汇总diff和测试结果，形成可审阅交付，不自动合并主分支。
5. 清理前检查未提交修改、未跟踪文件和任务状态，保留恢复路径。

**验收**：两个子任务修改同名文件但互不覆盖；脏工作树、分支重名、非Git目录、中文路径和失败回收正确；主工作树内容不被子任务误写。

**调优**：测量创建与依赖准备耗时，控制同时活动的工作树数；复用必须验证基准与归属。

### M15：Agent Teams

**交付**：长期成员、任务看板、持久消息队列、依赖和结果汇总。

**步骤**：

1. 定义team/member/task/message及生命周期和拥有者。
2. 实现任务领取、状态转换、依赖、取消、失败重派和重复领取防护。
3. 持久消息并使用messageId去重，限制队列和相互触发次数。
4. 协调者汇总交付与冲突，复用子Agent权限和Worktree隔离。
5. 恢复团队状态时检查成员和工作树，避免重复执行已交付任务。

**验收**：两个成员协作带依赖任务、消息重复/延迟、成员失败、协调者取消、恢复和冲突；任务不被双重执行，预算不随成员增加失控。

**调优**：测量调度延迟、闲置时间、消息量和总费用；只有独立且足够大的任务才启动团队。

5. 构建npm安装包，在干净环境检查bin、配置与资源路径；Windows人工验收，Linux CI，macOS验证。
6. 整理升级/回滚与已知限制，形成待发布版本；实际发布另按用户指示执行。

**验收**：类型/lint/测试/构建与固定回归通过；可安装并完成核心任务；权限和工作树检查通过；性能结果记录测试条件，已知限制明确。

**调优**：按最大瓶颈逐项优化；重复运行固定场景，确认收益并检查正确性没有退步。
