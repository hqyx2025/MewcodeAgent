# 项目讲解：从模型建议到可验证的工具任务

MewCode Agent是一个TypeScript + Node.js终端编程Agent学习项目。它把模型输出转换成受限工具调用，读取和修改代码、执行检查，并将结果交给下一轮模型。项目参考[公开介绍页](../../00-网页内容提取.md)的能力与章节主题，具体协议、权限、持久化和测试独立实现；未获得付费教程正文或课程源码。

## 两分钟讲解稿

我做的是一个本地CLI Coding Agent，技术栈是Node.js 24、TypeScript、Ink/React和npm。它支持流式对话、文件搜索读写、Shell、MCP，以及会话恢复和隔离子任务。模型适配支持OpenAI兼容的Chat Completions与Responses，还有Anthropic协议。

项目的核心是把“模型说要做什么”和“程序允许执行什么”分开。Agent Loop完整组装工具参数，验证协议后交给统一执行器；执行器检查模式、路径、规则和审批，才运行真实工具。写入要求读取版本匹配，Shell展示最终命令和工作目录。Plan模式在工具列表和执行器两处约束，外部文本不能放宽权限。

长任务采用有界上下文与JSONL检查点。压缩保留系统提示、目标、最近完整调用组和覆盖归档历史的指纹；摘要会省略细节，完整历史可查检查点。恢复保存已记录修改动作的指纹，阻止相同动作换一个callId后重新执行，但不能把外部副作用与本地日志变成原子事务。

协作分三层：只读SubAgent、有独立Git工作树的写入任务、带持久成员和依赖任务的Teams。它们共享预算并继承父权限。工作树保留脏修改和交付分支，汇总diff与真实检查，交付仍需人工审阅合并。

验证使用模拟provider和真实工具。M16固定五场景覆盖bug修复、重构、长会话恢复、MCP关闭和双成员修复，三平台自动化通过。我能说明这些工程行为，但尚未测量真实模型任务成功率和付费收益；Shell也具有当前用户主机权限，工程权限策略不等于操作系统沙箱。

这段稿件是讲解素材，第一人称应按自己的实际参与情况调整。未记录真人试讲时间，不把标题“两分钟”当成测得的口述时长。

## 沿一次修复讲实现

固定修复夹具中，`sum`把加法写成减法，Node断言先失败。脚本化provider请求读取文件，ReadFile给出revision；EditFile带回expectedRevision，将`a-b`改为`a+b`；再通过已批准的Bash运行检查，实际退出码变为0，最后核对文件内容。证据来自[M16夹具](../../../tests/support/release-evaluation.ts)的bug-fix，不把最后的“fixture checked”文本当成正确性判断。

自主模型在真实任务中需要自己定位和提出修改，是否做对取决于模型、仓库与测试。本地默认MockProvider只做固定协议演示，不会因为输入“修复bug”就推理任意代码；演示手册明确使用专门的脚本化夹具。
