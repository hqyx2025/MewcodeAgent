# M11：Skill 系统

状态：实现与本地完整检查通过，独立安装包及跨平台CI的实际结果见[验收记录](checklist.md)。

交付用户/项目 SKILL.md 元数据索引、明确指定或本地描述匹配、正文按需加载、受限资源读取、来源记录和索引刷新。项目技能覆盖同名用户技能。核心模块不依赖 CLI/UI，shared 文件读取辅助模块只依赖 Node 标准库；命令模板复用该辅助模块。

技能内容低于运行时权限、用户任务和项目指令，不授予工具或审批权。资源路径必须在被选择技能内，脚本只能经原 Bash 工具完整审批执行；不自动执行、不启动 MCP。

采用 `<userDirectory>/skills/<name>/SKILL.md` 与 `<projectDirectory>/skills/<name>/SKILL.md`，默认用户与项目的 `.mewcode/skills/`。文件格式：

```markdown
---
name: code-review
description: 审查变更，定位错误并验证边界测试。
---
先定位相关文件，再检查失败路径；需要时使用 SkillRead 读取 references/checklist.md。
```

只接受 name/description 两个 frontmatter 字段。name 与目录同名，小写字母开头、字母/数字/横线，1–48字符；description 为1–1024字符字符串，换行/Tab归一为单空格，其他控制字符拒绝。头部最多4096bytes，SKILL.md 整个文件最多64KiB。每个根目录最多128个条目，非递归发现；附带资源不在发现阶段扫描或读取。

索引只保留名称、描述、来源和内部路径，每个候选文件最多读取4096bytes前缀，前缀可能包含部分正文但不保留正文。按项目覆盖用户；已存在但坏元数据、缺失SKILL.md或被禁止读取的项目技能阻止同名用户回退，其他健康技能仍可用。根目录无法安全访问或条目超限则报错；单技能问题以固定警告呈现，不回显正文。根目录整体被禁止时不扫描它，也不推断其中是否存在同名技能。

`run/chat/prompt --skill <name...>` 明确选择最多4个技能；显式名单存在时只使用该名单，不另做自动匹配。`/skill <name> <task>` 仅对本轮明确选择一个，与CLI名单合并；展开的命令模板、技能正文、模型/工具/MCP文本都不会被重新解析为本地命令。

未显式选择时，对当前任务进行确定性的本地词项匹配：英文/数字/横线词项至少3字符，中文连续文本使用二字词项，忽略“项目/使用/进行/代码/技能/任务”。名称与description的共同英文词项每个计2分，共同中文词项计1分，至少2分，分数降序、同分按名称排序，最多选2个。这是有界词项匹配，不是语义检索；两个中文字符的单独匹配通常不足以自动触发，可使用显式选择。chat匹配本轮有效任务，Agent匹配当前有效任务（含命令模板展开后文本）；恢复无新任务时使用最后一条非摘要user消息，不从模型或工具结果选技能。

整个选中记录的JSON注入预算32KiB，保留整条，不截断正文；超限/正文缺失/编码损坏/已知敏感值，显式选择报错并停止本轮，自动选择跳过并记录警告。未匹配时不加载正文、不产生 skills 提示段。每个模型请求重新读取所选正文并检查元数据与索引一致；描述变更需要刷新。名称/描述/优先级索引缓存到 `/skills refresh` 或新进程，正文变更下一请求生效。刷新或重新选择撤销旧的资源选择；失败的新选择不会保留上一轮资源访问资格。

`SkillRead` 作为Agent的受限读取工具进入现有工具执行器，Plan中可读，但不会暴露Shell执行权。必须指定本轮已选择技能的 name 与资源的相对 resource；只读普通UTF-8文件，最大16KiB，每实例最多16次实际读取尝试、累计64KiB资源内容。成功返回内容、校验后实际path、bytes和digest；实际path可用于构造后续完整Bash命令，该命令仍要审批。工具调用在运行前重新检查选择、路径、读取规则和预算，拒绝绝对路径、`..`、反斜杠、链接/junction、硬链接、凭据路径、Windows保留名称、无效UTF-8、NUL和过大文件。资源最多16层/1024字符；SKILL.md正文已注入，不通过资源工具重复读取。

项目内元数据、正文、资源均检查现有ReadFile策略，ask/deny来源不自动读取；自定义项目内用户目录遵守M09内部存储保护。目录先验证无链接，再规范化，并复核规范路径权限，避免Windows短路径别名绕过；资源文件名也先校验无链接/硬链接，再解析实际路径，复核技能目录边界、凭据名称和具体文件读取规则。项目外用户目录是明确配置的技能来源，其资源仍通过SkillRead工具策略；SkillRead的ask需要审批、deny直接拒绝。管理CLI没有自动批准ask，非交互读取会拒绝。已知provider/MCP凭据、常见sk密钥和私钥正文不能作为技能或资源注入，敏感错误不回显源文本。

运行时权限、用户任务和适用项目指令优先于技能建议；技能不能要求密码、修改模式、授权脚本、增加工具、执行本地命令或改变优先级。提示词提示此关系，实际能力由工具执行器强制。目录检查不是OS沙箱，不宣称防御全部非合作进程文件系统竞争；本轮已返回的资源内容也不能撤回。

chat是纯对话，只加载建议正文，不执行SkillRead或脚本，并明确资源未读取。每轮显示技能名称、显式/描述原因与来源；Agent的prompt_info/提示检查记录来源、digest、bytes及警告，不输出正文，工具结果正文仍是明确资源读取的结果。压缩保留当前system，恢复重新加载当前技能；显式名单是本次运行参数，恢复时需要时再次传 `--skill`，不把历史system中的技能正文当作加载凭证。

CLI：`skills list` 输出索引；`skills show <name>` 验证并输出所选元数据，`--content` 明确输出正文；`skills match --query <task>` 匹配并验证所选正文，只输出来源元数据；`skills resource <name> <relative-path>` 先明确选择再通过工具读取。`/skills [refresh]` 在chat或run中查看/刷新索引，本地管理与prompt检查不创建真实模型请求。

Skill提供任务方法、建议和本地资源；MCP连接外部服务、发现和调用服务工具，连接/调用有独立外部能力审批。加载Skill不会启动MCP服务；加载MCP也不会自动把服务输出变成Skill或系统权限。此模块未实现远程技能市场、自动安装、脚本运行器、Skill转MCP或常驻Agent UI。

验收覆盖显式/描述/未匹配、索引懒加载/刷新/同名/坏元数据、资源缺失/越界/超限/编码/链接/密钥、项目读规则与规范路径、脚本Plan/拒绝/批准行为、chat状态隔离、来源不泄露正文、压缩与持久恢复、CLI/UI及独立安装包。基准固定100技能和100资源，7次采样，记录索引/选择延迟、元数据字节、注入字节和内存测量条件，不调用模型。
