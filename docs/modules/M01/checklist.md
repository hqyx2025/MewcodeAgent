## 性能基线与已完成调优

安装验证会在同一台机器的临时中文/空格目录中执行7次`node <安装入口> --help`，测量完整子进程墙钟耗时。比较条件为同一Node版本、相同命令与生产依赖，不包含PowerShell启动时间或网络安装时间。

| 指标 | 单文件构建 | 按需拆分后 |
| --- | --- | --- |
| help耗时中位数 | 109.42 ms | 40.04 ms |
| 最终help最小/最大 | — | 39.75 / 40.32 ms |
| CLI入口文件 | 18,049 bytes | 5,166 bytes |
| 最终所有编译JS合计 | — | 17,012 bytes |
| 最终npm压缩包 | — | 22,384 bytes |
| 最终包解压大小 | — | 69,571 bytes，含README、许可证、source map等，不含外部依赖 |
| tsup输出构建阶段 | 52 ms | 57 ms，不包含安装与完整检查 |
| 最终离线demo总耗时 | — | 302.26 ms，单次采样，含模拟分片延迟 |

原因：单文件构建将动态加载模块的外部依赖提升到入口，help也会初始化Zod和YAML。启用ESM代码拆分后，入口仅加载CLI与基础错误，配置和Mock按需加载。本次help中位数下降约63%；这是一台机器上的局部启动优化，不能外推到模型响应或所有系统。

安装回归使用Node模块加载钩子阻止Zod/YAML导入，再执行help/version，验证性能边界没有随着打包变化失效。Windows下加载钩子路径使用file URL，修复了直接传盘符路径时的ESM协议错误。
